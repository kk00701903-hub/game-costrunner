# 범용 게임 개발 표준 워크플로우

1인·소규모 팀이 AI(Claude)와 툴 체인을 묶어 Unity 3D 게임을 만들 때의 **표준 5단계 파이프라인**이다.  
도구는 교체 가능하지만, **Phase 순서와 산출물 계약**은 유지한다.

| Phase | 역할 | Claude 역할 | 툴 체인 | 산출물 |
|------:|------|-------------|---------|--------|
| 1 | 기획·시스템 설계 | 총괄 디렉터 / 테크 리드 | Claude → GitHub | GDD, 마일스톤, Issue Task |
| 2 | 시각·UI/UX | 아트 디렉터 | Claude → Firefly/PS → Figma | 컨셉·아이콘·UI 와이어 |
| 3 | 3D·애니메이션 | 모델링/리깅 가이드 | Claude → Blender → Mixamo | FBX, 애니 클립 |
| 4 | 영상·컷씬 | 연출 / 샷 리스트 | Claude → Kling AI | 트레일러·컷씬 영상 |
| 5 | 엔진 조립·코드 | 시니어 프로그래머 | Claude → Unity → GitHub | 플레이어블 빌드, 커밋 |

---

## Phase 1 — 기획 및 시스템 설계 (Claude → GitHub)

가장 먼저 프로젝트의 **전체 청사진**과 **태스크 관리**를 잡는다.

### Claude 지시 프롬프트 예시

> 너는 지금부터 유니티 기반 3D 게임의 총괄 디렉터 겸 테크 리드야. 동물의 숲과 유사한 게임을 1인 개발로 만들 예정이야. 먼저 핵심 게임 루프를 포함한 GDD(게임 기획서)를 작성하고, 이를 바탕으로 GitHub Projects(칸반 보드)에 등록할 수 있도록 마일스톤과 이슈 트래커용 작업 단위(Task)를 마크다운 리스트로 쪼개줘.

### 실제 작업

1. Claude가 작성한 GDD를 레포 `Docs/`(또는 기획 폴더)에 저장한다.
2. Task 리스트를 **GitHub Issues**로 등록한다.
3. **GitHub Projects** 칸반(Todo / In Progress / Done)에 이슈를 올려 진척도를 관리한다.

### 이 Phase의 완료 기준

- [ ] 핵심 루프 1문단 + 시스템 목록이 GDD에 있다
- [ ] 마일스톤(예: Vertical Slice / Alpha / Beta / Ship)이 정의됐다
- [ ] 칸반에 올릴 수 있는 Task 단위로 쪼개져 Issue에 등록됐다

---

## Phase 2 — 시각 디자인 및 UI/UX (Claude → Firefly/Photoshop → Figma)

컨셉을 시각화하고 UI를 설계한다. Claude를 **아트 디렉터**로 쓴다.

### Claude 지시 프롬프트 예시

> 기획한 게임의 따뜻하고 아기자기한 톤앤매너에 맞게, 메인 UI(인벤토리, 대화창)와 텍스처를 만들려고 해. Adobe Firefly에 입력할 '영문 프롬프트' 5가지를 생성해 주고, Figma에서 모바일/PC 해상도에 맞춰 UI를 어떻게 배치해야 하는지 컴포넌트 계층 구조를 텍스트로 설계해 줘.

### 실제 작업

1. Claude가 준 **영문 프롬프트**를 Firefly에 넣어 텍스처·아이템 아이콘·컨셉 아트를 생성한다.
2. Photoshop으로 배경 제거(누끼)·게임 에셋용 정리(해상도·알파·네이밍).
3. 정리한 이미지를 Figma로 가져와, Claude가 설계한 **컴포넌트 계층**대로 버튼·패널을 배치해 UI 와이어프레임을 완성한다.

### 이 Phase의 완료 기준

- [ ] 톤앤매너 레퍼런스 + Firefly 프롬프트 세트가 문서화됐다
- [ ] 핵심 UI(인벤토리·대화 등) 와이어가 모바일/PC 해상도로 있다
- [ ] Unity로 넘길 에셋 네이밍·해상도 규칙이 정해졌다

---

## Phase 3 — 3D 모델링 및 애니메이션 (Claude → Blender → Mixamo)

Claude는 3D 툴을 직접 조작하지 못하지만, **bpy 스크립트**와 **모델링·리깅 규격**을 지시할 수 있다.

### Claude 지시 프롬프트 예시

> 주인공 캐릭터를 블렌더에서 로우폴리 스크립트로 모델링하려고 해. 캐릭터의 폴리곤 최적화 가이드를 알려주고, 유니티와 믹사모(Mixamo) 호환을 위해 T-Pose로 만들 때 주의해야 할 리깅(Rigging) 조건을 정리해 줘.

### 실제 작업

1. 가이드(또는 bpy)로 Blender에서 기본 형태를 만든다. (Firefly 텍스처를 UV에 매핑해도 됨)
2. 완성 모델(`.fbx`)을 Mixamo에 업로드 → 오토리깅
3. `걷기 / 뛰기 / 채집 / 인사` 등 필요 애니를 다운로드한다

### 이 Phase의 완료 기준

- [ ] T-Pose + Mixamo/Unity Humanoid 호환 뼈 규격이 문서화됐다
- [ ] 플레이어(또는 핵심 NPC) FBX + 기본 이동/액션 클립이 있다
- [ ] 폴리 예산·스케일(미터)이 Unity Import 설정과 맞다

---

## Phase 4 — 영상 및 컷씬 연출 (Claude → Kling AI)

오프닝·시네마틱·배경 영상이 필요할 때 사용한다.

### Claude 지시 프롬프트 예시

> 게임 시작 시 나오는 15초짜리 오프닝 트레일러를 만들 거야. Kling AI 비디오 생성기에 입력할 장면별(Scene 1, Scene 2...) 카메라 워크와 피사체의 움직임을 묘사하는 프롬프트를 영어로 작성해 줘.

### 실제 작업

1. Claude가 작성한 **샷 리스트 / 영문 프롬프트**를 Kling에 입력한다.
2. 고품질 컷씬·트레일러 클립을 추출·편집해 프로젝트 미디어 폴더에 넣는다.

### 이 Phase의 완료 기준

- [ ] 장면별 영문 프롬프트(카메라 + 피사체 동작)가 문서에 있다
- [ ] 오프닝/컷씬용 영상이 해상도·길이 스펙에 맞게 확보됐다

---

## Phase 5 — 유니티 엔진 조립 및 프로그래밍 (Claude → Unity → GitHub)

에셋이 모이면 Unity에 올리고 Claude를 **시니어 프로그래머**로 쓴다.

### Claude 지시 프롬프트 예시

> 이제 유니티(C#)에서 작업을 시작할 거야. 믹사모에서 가져온 애니메이션을 제어할 플레이어 상태 머신(FSM) 코드를 작성해 줘. 그리고 피그마에서 설계한 인벤토리 UI를 연동하기 위해, 데이터 기반(Scriptable Object)의 아이템 관리자 시스템 스크립트도 함께 짜줘. 코드는 복사해서 바로 쓸 수 있게 최적화해 줘.

### 실제 작업

1. Blender / Mixamo / Photoshop 에셋을 Unity로 임포트한다.
2. Claude가 준 C#을 적용하고, 콘솔 에러 로그를 그대로 붙여 넣어 디버깅을 지시한다.
3. **기능 단위로 GitHub에 커밋**한다. (선택: GitHub Actions로 자동 빌드·배포)

### 이 Phase의 완료 기준

- [ ] Vertical Slice가 플레이 가능하다 (이동 + 1개 핵심 루프 + 기본 UI)
- [ ] Issue/칸반 상태가 코드 커밋과 대응된다
- [ ] (선택) CI로 빌드 또는 패키지 산출이 돌아간다

---

## 운영 규칙 (권장)

1. **한 Phase의 산출물이 다음 Phase의 입력**이 되게 한다. (GDD → 아트 톤 → 리그 규격 → 샷 리스트 → 코드 계약)
2. Claude에게는 항상 **역할 + 산출물 형식 + 바로 쓸 수 있는 형태**(마크다운 Task, 영문 프롬프트, 복붙용 C#)을 요구한다.
3. 진척은 **GitHub Issue / Projects**만 본다. 채팅 기록은 보조다.
4. 에셋·코드 네이밍은 초기에 고정하고, Phase 2~5에서 바꾸지 않는다.
5. 커밋은 “기능 하나 = 커밋 하나”를 기본으로 한다.

## 프로젝트별 적용

이 문서는 **장르·IP와 무관한 범용 표준**이다.  
실제 프로젝트(예: Coast Run / 제때 런)에서는 아래만 바꿔 쓴다.

- GDD 경로, 번들 ID, 타깃 해상도
- 사용 중인 원격 레포·브랜치 규칙 (`Docs/REPOS.md` 등)
- 이미 있는 엔진/파이프라인(자체 리그, 자체 BGM 슬롯 등)과의 매핑

새 게임을 시작할 때: **Phase 1부터 이 README의 체크리스트를 복사**해 Issue 본문으로 붙이면 된다.
