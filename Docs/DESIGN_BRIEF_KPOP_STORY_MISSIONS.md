# 설계 요청서 — K-POP 데일리 러닝 · 스토리 미션 강화

**대상:** Claude (설계 전담)  
**프로젝트:** Coast Run / 「너와 나의 주파수」 (`C:\dev\game`)  
**작성일:** 2026-09-11  
**목적:** 구현 코드가 아니라 **게임 디자인 문서(GD)** 를 작성해 달라. 아래 두 모드를 재설계하고, 기존 코드·시스템과의 연결 포인트를 명시하라.

---

## 0. 한 줄 요청

1. **K-POP 모드** → 약 **1분 30초** K-POP을 들으며 달리고, **매일 접속할 이유**가 있게. Subway Surfers + Temple Run의 강점을 흡수한 설계.
2. **스토리 모드** → 스토리를 “그냥 지나가는” 구간이 아니라, **스토리를 깨는(진척·분기·보상과 묶인) 미션**으로 게임성을 올려 달라.

산출물은 **설계도** (루프 / 세션 길이 / 보상 / UI 플로우 / 챕터별 미션 표 / 리스크·우선순위). 구현 범위·페이즈 제안까지 포함.

## 1. 현재 상태 (사실 — 설계의 출발점)

### 1-1. 코스 동질성
- CH1~20은 **같은 3레인 직선 프로미네이드** + `SceneMix` 좌우 풍경 배합·낮/밤·계절 틴트만 다름.
- 뛰는 손맛은 “20개 맵”이 아니라 **한 코스의 스킨 교체**에 가깝다.  
  → 모드 차별화는 **맵 교체보다 세션 구조·미션·보상·음악 동기화**로 풀 것.

### 1-2. K-POP 러닝모드 (지금)
| 항목 | 현황 |
|---|---|
| 진입 | 타이틀 하단 **K-POP 러닝모드** |
| 코드 | `ArcadeRun.StartKpop` → `ArcadeKind.Endless` + `KpopMode=true` |
| 길이 | **무한**(사망 시 결과). 스토리 골인 리본 없음 |
| BGM | `BGM_KPOP_1…` 순서 재생 |
| 코스 | 챕터 선택(자동=마지막 클리어+1) → 해당 `SceneMix` |
| 육성 | 세이브 있으면 스탯·펫·러닝/보드 적용 |
| 데일리 | **없음** (별도 `ArcadeKind.Daily` 「오늘의 런」은 존재하나 K-POP과 분리) |

**문제:** 끝없이 달리면 질림. 매일 켤 훅이 약함. 음악이 세션의 “한 곡 완주” 경험이 아님.

### 1-3. 이미 있는 아케이드 자산 (재사용 후보)
- `ArcadeRun` Endless / Daily — Daily는 날짜 시드 + 조건 3개 + 도장·스트릭 (`MakeConditions`).
- `MissionKind`: NearMiss, Coins, Combo, Hearts, MaxHits, Fast, NoHit.
- Meta: `dailyStreak`, `DailyCount`, endless best 등.

### 1-4. 스토리 모드 (지금)
| 층 | 내용 |
|---|---|
| 루프 | 육성 → (게이트) → 러닝 CH → 컷씬 → 다음 |
| 러닝 별 | `MissionTable` 챕터당 **별 2개**(선택 달성, 팬아트 해금용) |
| 미니게임 | `ChapterMission` — CH3/6/9/12/14 클리어 후 **윷·구슬 등** (롱컷 직전 게이트) |
| 게이트 | `StoryGate` 체력 요구 |
| 컷씬 | `ChapterVN` + `Tools/Story/script/` |

**문제:** 러닝 미션이 “통계 조건 2개” 수준이라 **스토리 사건과 약하게만 연결**됨. 챕터 장소·대사·관계 변화가 플레이에 거의 안 드러남. 미니게임은 소수 챕터만.

관련 문서: `Docs/STORY_MODE_v6.md`, `Docs/RAISING_TAMAGOTCHI_v3.md`.

## 2. K-POP 모드 — 설계 목표

### 2-1. 플레이 판타지
> 「버스/이어폰 끼고 **한 곡** 동안만 해안을 달린다. 오늘도 왔으면 도장. 잘하면 하이라이트·캐릭터·펫 보상.」

### 2-2. 필수 스펙 (제품 지시)
| # | 지시 | 설계에서 구체화할 것 |
|---|---|---|
| A | **세션 ≈ 1분 30초** | 거리≈속도×90초 환산, 골인/페이드아웃, “한 곡 길이”와 BGM 정렬(트랙이 더 길면 훅 구간만 / 루프 컷 등 옵션 비교) |
| B | **매일 접속** | 일일 미션 3개, 스트릭, 오늘만의 시드/테마, 놓치면 FOMO 수준(과하지 않게) |
| C | **Subway Surfers 장점 흡수** | 예: 짧은 세션·일일 챌린지·캐릭터/보드 수집 훅·점수·주간 하이라이트·쉬운 재도전. **우리 게임에 맞게 번역** (무단 표절 금지, 메커닉 원리만) |
| D | **Temple Run 장점 흡수** | 예: 속도감·위험 고조·파워업/무적 타이밍·“한 번 더” 긴장. 세로 모바일·3레인에 맞게 |

### 2-3. 레퍼런스에서 가져올 / 버릴 것

설계 문서에 표를 만들어라.

| 레퍼런스 | 가져올 원리 | Coast Run에 옮기는 형태 | 버릴 것 |
|---|---|---|---|
| Subway Surfers | … | … | … |
| Temple Run | … | … | … |

금지: 과도한 IAP 압박, 무한 광고 게이트, 원작 IP 카피 UI.

### 2-4. 제안해야 할 설계 블록
1. **세션 루프** (타이틀 → 오늘의 3미션 확인 → 러닝 90초 → 결과 → 도장/스트릭 → 육성/컬렉션 연결 여부)
2. **클리어 조건** (거리 / 생존 / 미션 N개 / 곡 끝 동시 골인 중 권장안 + 대안 1개)
3. **일일 콘텐츠** (미션 풀, 시드, “오늘의 트랙/챕터 스킨”, 스트릭 보상 곡선)
4. **점수·리더보드(로컬)** — 서버 없음 전제. 기존 MetaProfile 필드와의 매핑
5. **음악** — `BGM_KPOP_*`와 90초의 관계, 비트/드롭에 맞춘 이벤트(선택: fever·코인 레인 펄스) — 과도하면 구현 비용↑이니 **Must / Nice** 분리
6. **기존 Daily(오늘의 런)와의 관계** — 통합 / K-POP이 Daily를 대체 / 병행 중 하나 권장 + 이유
7. **Endless “노을 달리기”와의 역할 분리** — K-POP=짧은 데일리 훅, Endless=장거리 스코어 어택 등
8. **UI 와이어** (타이틀 바, 미션 HUD, 결과 카드) — 텍스트 레벨 스케치면 충분
9. **경제** — 코인/하트/펫 경험/팬아트와의 하루 보상 상한 (스토리·육성 밸런스 깨지 않게)

### 2-5. 성공 지표 (설계 가정)
- 평균 세션 90±15초
- D1 재방문 동기: “오늘 도장 / 미션 1개라도”
- “질린다” 피드백이 맵이 아니라 **미션·음악·보상** 쪽으로 이동

## 3. 스토리 모드 — 설계 목표

### 3-1. 플레이 판타지
> 「이 챕터의 **이야기 사건**을 러닝으로 해낸다. 미션을 깨야 관계가 열리고, 별·엔딩·사이드가 의미 있게 바뀐다.」

### 3-2. 필수 스펙
| # | 지시 | 설계에서 구체화할 것 |
|---|---|---|
| A | **스토리를 깨는 미션** | 챕터 Open/Close·장소(`ChapterLocation`)·캐릭터 관계와 **서사적으로 연결된** 러닝 목표. “코인 N개”만의 반복 지양 |
| B | **게임성 향상** | 실패/재도전 의미, 선택지(미션 A vs B), 클리어 시 컷씬·육성·엔딩 플래그 연동 |
| C | **기존 자산 활용** | `MissionTable` 확장/교체, `ChapterMission` 미니게임 배치 재검토, VN 태그/`SaveData` 플래그 |

### 3-3. 미션 유형 아이디어 (설계에서 정제·표로 20챕터 배정)
예시 — Claude가 보완·폐기·추가:

| 유형 | 예 | 스토리 연결 |
|---|---|---|
| 호위/전달 | N초 안에 하트 M개 | “약을/편지를 챙긴다” |
| 추적/도주 | 무피격 구간 / 니어미스 | “뒤쫓기·숨기” |
| 축제/시장 | 코인·콤보 | CH8 동문시장 |
| 밤/안개 | 시야·피격 제한 | CH6·9·11·13·17 밤 챕터 |
| 관계 | 특정 픽업만 / 피버 타이밍 | 도담·루아 등 |
| 게이트 연동 | 미션 실패 시 체력 소모·주 연장 옵션 | `StoryGate`와의 관계 |

### 3-4. 제안해야 할 설계 블록
1. **챕터당 미션 구조** (예: 필수 1 + 별 2, 또는 스토리 비트 3개 중 2개 성공 등) — 권장안 1 + 대안
2. **CH01~20 미션 표** (장소명 · 스토리 한 줄 · 필수 미션 · 별 미션 · 보상/플래그)
3. **실패 시 플로우** (즉시 재도전 / 육성 복귀 / 스토리 약화 분기)
4. **미니게임(`ChapterMission`) 재배치** — 유지·확대·러닝 미션으로 흡수 중 권장
5. **엔딩·사이드 스토리**와의 연결 (별 총량, 특정 미션 클리어 비트)
6. **난이도 곡선** — 초반 튜토리얼성 → 중반 관계 갈등 → 후반 압박
7. **K-POP 모드와의 경계** — 스토리 미션 보상 ≠ 데일리 보상 중복 과다 방지

### 3-5. 성공 지표
- “왜 이 챕터를 달리나”가 대사/미션 UI만 봐도 이해됨
- 스토리 플레이어가 별/미션을 **의도적으로** 노림
- 러닝이 컷씬 사이 **의미 있는 행위**로 느껴짐

## 4. 두 모드 관계 (반드시 명시)

```
타이틀
├─ 스토리(이어하기) … 육성 + 서사 미션 러닝 + VN
├─ K-POP 데일리 … 90초 · 매일 · 음악 · 가벼운 수집
└─ (선택) Endless 노을 … 장거리 스코어 (역할 유지 or 축소)
```

- 일일 시간 예산 가정: K-POP 2~3분 + 스토리 한 챕터 조각.
- 신규 유저: 어느 버튼을 먼저 눌러야 하는지 온보딩 한 줄.

## 6. 제약·톤

- 모바일 **세로** 러너. 서버 없는 로컬 세이브 전제.
- 제주·청춘·관계 톤 유지. K-POP은 **캐주얼 훅**, 스토리는 **감정·관계**.
- 코스 아트 대규모 신제작 전제하지 말 것 (`SceneMix`·기존 프랍으로 충분하다고 가정).
- 기존 한글 카피 톤: 짧고 따뜻하게 (`Loc.T` 패턴).

## 8. 요청 문장 (복붙용)

> Coast Run의 **K-POP 모드**를 Subway Surfers·Temple Run의 장점을 흡수해 **약 1분 30초 한 세션 + 매일 접속 루프**로 재설계하고, **스토리 모드**는 챕터 서사와 연결된 **스토리 클리어 미션**으로 게임성을 높이는 설계 문서를 작성해 줘. 현재는 CH1–20 코스가 사실상 동일하고, K-POP은 무한 러닝, 스토리 미션은 통계형 별 2개·소수 미니게임 수준이야. `Docs/DESIGN_BRIEF_KPOP_STORY_MISSIONS.md`를 따르고, 구현이 아니라 GD 산출물만 내 줘.
