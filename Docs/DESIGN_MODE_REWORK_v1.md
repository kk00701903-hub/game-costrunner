## 1. Executive summary

1. **K-POP 모드 = 「한 곡 달리기」.** 무한 러닝을 버리고 **세션 ≈ 90초 = 곡 한 구간**이 되게 한다. BGM은 **레코드 M2 「솜사탕 둘이서」· M4 「Goodbye My First Love」· M7 「보조개」 중 매 런 랜덤 1곡**(사용자 확정, `BGM_KPOP_*` 파일은 없음). 골인은 "곡 구간이 끝나는 순간" — 마지막 후렴이 피버(하이라이트 구간)이고, 아웃트로에 리본을 끊는다.
2. **매일 켤 이유 = 도장 + 3미션 + 스트릭.** 곡을 한 번 완주하면 그날 도장(스트릭 유지), 오늘의 미션 3개를 다 채우면 「올클리어」 보상. 코스·미션은 날짜 시드라 "오늘의 코스"가 하루 동안 같다.
3. **기존 「오늘의 런」(`ArcadeKind.Daily`)은 K-POP에 흡수.** 도장·스트릭·조건 3개·날짜 시드 코드를 그대로 K-POP이 쓴다. Endless 「노을 달리기」는 K-POP 화면 안의 「자유 달리기」 토글로 남긴다(장거리 스코어 어택 역할).
4. **Subway Surfers에서는 "짧은 세션·일일 챌린지·수집 훅·쉬운 재도전"의 원리를, Temple Run에서는 "속도 고조·위험 구간·한 번 더" 긴장을** 가져오되, 형태는 우리 것(꼬마 피버·펫·방 장식·레코드)으로 번역한다. IAP 압박·광고 게이트·원작 UI 카피 없음.
5. **스토리 모드 = 챕터마다 「이야기 비트」 1개 + 별 2개.** 비트는 그 챕터의 사건(편지 호위, 초 지키기, 뒷모습 따라가기, 혼자 일어서기…)을 러닝 목표로 번역한 것. 실패해도 도착하면 챕터는 넘어가지만, 컷씬 분기·하트·별이 달라진다(연성 실패, 「늦음」 규칙과 같은 층).
6. **새 미션 종류 6개**(구간 무피격·초 지키기·편지 호위·돌탑 순서·뒷모습 페이서·꼬마 없이)를 `MissionKind`에 추가하고, 컷씬 조건 태그 `[비트==1]`로 대본과 연결한다.
7. **미니게임 5개(CH3·6·9·12·14)는 유지**하되 새 대본 인물·톤으로 이름·규칙 문구만 바꾼다. 러닝 미션으로 흡수하지 않는다(롱컷 직전 리듬 변화가 오히려 좋다).
8. **경제 상한:** K-POP 하루 코인 상한 ≈ 스토리 한 챕터 러닝(≈100G)과 같은 수준. 스토리 미션 보상은 코인이 아니라 **별·하트·컷씬 분기·엔딩 플래그** — 데일리 보상과 겹치지 않는다.
9. **P0(1주)** 는 기존 코드 재사용만으로 끝난다: 90초 타이머·곡 끝 골인·날짜 시드·미션 3개(`MakeConditions` 값 재조정)·도장/스트릭(기존 필드)·MissionTable 문구 교체·`[비트]` 태그. 새 메커닉(페이서·초)은 P1~P2.
10. **결정 필요:** M2·M4·M7 후렴 시각·90초 창 시작점, 보너스 레코드 잠금과의 관계, 「오늘의 런」 흡수 확정, 스토리 비트 실패를 연성/경성 중 어느 쪽으로, 새 대본 인물명(하늘·바다·도윤)과 기존 코드(도담·루아·만수) 정리.

## 3. K-POP 모드 — 「한 곡 달리기」

### 3-1. 플레이 판타지
> 이어폰 끼고 **한 곡** 동안만 해안을 달린다. 후렴에서 꼬마가 피버를 틀어 주고, 곡이 끝나면 리본. 오늘도 왔으면 도장.

### 3-2. 레퍼런스 번역표

| 레퍼런스 | 가져올 원리 | Coast Run에 옮기는 형태 | 버릴 것 |
|---|---|---|---|
| Subway Surfers | 짧은 세션, 언제든 재시작 | 곡 1개 = 세션. 결과 카드에서 「한 곡 더」 1탭(로딩 없이 같은 씬 리트라이 = `RetryCurrent`) | 무한 러닝, 부활 유료 |
| | 일일 챌린지(글자 모으기) | 오늘의 미션 3개 + 「오늘의 하이라이트 레인」(후렴 구간 코인 레인이 날짜별로 정해짐) | 실물 상품·서버 이벤트 |
| | 캐릭터·보드 수집 훅 | 펫(4종+)·러닝/보드 모드·방 장식 드롭(`RoomDeco.TryDropFromRun` 이미 있음)·레코드 해금 | 가챠, 코인 인플레 |

### 3-4. 클리어 조건 — 권장안 + 대안

| | 권장안 A: 곡 끝 = 골인 | 대안 B: 고정 거리 1,200 m |
|---|---|---|
| 정의 | 곡 재생이 끝나는 순간(또는 `KpopSessionSeconds`=90) 리본. 거리는 결과일 뿐 | 스토리처럼 `targetDistance`=1,200 m, 곡은 배경 |
| 장점 | "한 곡 완주" 판타지 그대로. 속도가 달라도 항상 90초 | 기존 `StageDef`/리본/클리어 코드 그대로 |
| 단점 | 리본 위치를 시간으로 산출해야 함(`speed×남은시간`으로 마지막 세그먼트에 배치) | 빠르면 곡이 남고 느리면 곡이 먼저 끝남 |
| 구현 | `ArcadeRun.KpopMode`일 때 `StageManager`가 targetDistance 대신 **시간 트리거**로 `FinishRibbon` 생성. 곡이 없으면 90초 고정 | 없음 |

**권장: A.** 트랙 3곡의 길이가 제각각(M4 97s / M7 202s / M2 233s)이므로 **"곡 전체"가 아니라 "곡의 90초 구간"** 을 세션으로 쓴다:

| 트랙 | 길이 | 재생 방식(제안) | 후렴 시각(제안, 사운드 확인 필요) |
|---|---|---|---|
| M4 Goodbye My First Love | 97.1s | **통째로**(세션 97초). 마지막 5초 자연 아웃트로 | 55~80s |
| M7 보조개 | 201.6s | **90초 창**: 파일 안의 `start`부터 90초, 마지막 3초 페이드아웃 | 창 안 55~80s |
| M2 솜사탕 둘이서 | 232.9s | 위와 같음(90초 창) | 창 안 55~80s |

`KpopTrackMeta { key, start, length, chorusStart, chorusEnd }` 상수표 3줄로 관리(초기값 start=0, length=90, 55/80). 오프라인 편집본을 만들 필요 없이 `AudioSource.time = start`로 시작하면 되고, 사운드 담당이 후렴 위치만 채워 준다. 세션 길이는 곡 창 길이(90 또는 97초)를 따른다. 비트 검출·루프 컷은 하지 않는다.

### 3-5. 일일 콘텐츠

**시드:** `Seed = Today(yyyyMMdd)` — `ArcadeRun.Start(Daily)`와 동일. `ObstacleSpawner.SeedOverride=Seed`로 하루 동안 같은 코스. 「자유 달리기」만 `TickCount`.

**곡 선택:** **매 런 M2 / M4 / M7 중 랜덤 1곡**(사용자 확정). 같은 곡 연속 회피(직전 곡 제외 후 2택). 코스 시드는 날짜 고정이지만 곡은 런마다 바뀌므로 "같은 코스, 다른 곡"이 하루의 변주가 된다. 결과 카드와 HUD에 곡 제목(`RecordTable.All[n].ko`) 표시.

**오늘의 코스 스킨:** 챕터 = `KpopChapter(gm)` 그대로(자동=마지막 클리어+1, 또는 선택). 스킨은 `SceneMix`·`ChapterClock`·계절 틴트가 이미 챕터별로 다르므로 추가 아트 없음.

**미션 풀 (90초 기준으로 값 재조정 — `MakeConditions` 교체):**

|---|---|---|---|

| NearMiss | 6~14 | "아슬아슬 {n}번" / "{n} near misses" | |

3개 = Finish(고정) + 풀에서 2개(같은 종류 중복 없음). 난이도는 요일로 살짝 흔든다(주말 +10%).

**도장·스트릭 (기존 필드 재사용):**
- 도장 = 그날 **첫 완주**(`lastDailyDate != Today`) → `dailyStamps += Today`, `dailyStreak` 갱신. 미션 3개와 무관.
- 올클리어 = 미션 3개 모두 ✓(같은 런이 아니어도 됨 — 하루 누적 `kpopMissionDoneMask`).
- 스트릭 보상 곡선(과하지 않게): 3일 장식 상자(방 장식 1), 7일 레코드 조각 또는 포토카드 1장(`cardMask` 미획득 중), 14일 펫 스킨 색(P2), 30일 칭호. 스트릭이 끊겨도 잃는 건 없다(FOMO는 "🔥N이 0이 된다"까지만). 하루 1회 「어제 놓침 → 오늘 2곡 완주로 복구」 옵션(P1).

## 4. 스토리 모드 — 「이야기를 깨는 미션」

### 4-1. 플레이 판타지
> 이 챕터의 **사건**을 러닝으로 해낸다. 편지를 지키고, 초를 꺼뜨리지 않고, 그 사람의 뒷모습을 놓치지 않고, 마지막엔 꼬마 없이 혼자 일어선다.

### 4-2. 챕터당 미션 구조 — 권장안 + 대안

| | 권장안 A: 비트 1(연성) + 별 2 | 대안 B: 비트 3개 중 2개 성공(경성) |
|---|---|---|
| 클리어 | **도착**하면 챕터 클리어(기존). 비트 성공 여부는 `Save.chapterBeat[ch]`에 기록 | 비트 2/3 미만이면 클리어 실패 → 재도전 |
| 실패의 의미 | 클로즈 컷씬이 `[비트==0]` 분기(짧고 쓸쓸한 버전), 하트 ×0.6(「늦음」과 같은 층), ★ 비트 별 미획득, 엔딩 카운트에 반영 | 게이트·노을·비트 3중 실패 → 좌절 위험 |
| 별 | ★1 도착(기존 bit0) · ★2 **비트 성공**(bit1) · ★3 챕터 별미션(bit2) | 별 = 비트 수 |
| 장점 | 스토리 플레이어가 막히지 않음. "노을 전에 도착" 규칙과 문법이 같음 | 긴장 최대 |
| 단점 | 비트를 무시하고 달릴 수 있음 → 비트 실패 시 **연출로 체감**시켜야 함(편지가 날아가는 컷, 초가 꺼지는 컷) | 육성 게이트와 겹쳐 진행 정체 |

**권장: A.** 이미 체력 게이트(경성)와 노을(연성)이 있으므로 비트는 연성. 단 **CH20만 경성**(혼자 일어서기 실패 = 재도전, 이야기의 클라이맥스).

**미션 선택지(A vs B)**: 챕터 진입 카드에서 별미션(★3)을 **두 개 중 하나 고르기**(예: "코인 90" vs "무피격"). `MissionTable`에 슬롯 3개를 두고 UI에서 고른 것만 판정. 실패해도 다음 재도전에서 바꿀 수 있다. (P1)

### 4-3. 새 미션 종류 (`MissionKind` 확장)

| 종류 | 판정 | 필요한 훅 | 서사 |
|---|---|---|---|
| `NoHitLast` | 마지막 30% 구간 무피격 | `StageRunStats`에 구간별 SoftHits(거리 3분할) | "마지막 오르막은 넘어지지 않고" |
| `NoHitFirst` | 첫 30% 무피격 | 위와 같음 | "출발은 조심히"(튜토리얼) |

| `SkyCoins` | 활공 코인 N개 | 33차 하늘 코인 카운트 | CH12 오름 능선 활공 |

`Pacer`·`Escort`·`Candle`·`Stones`는 새 오브젝트가 필요하므로 P1~P2. P0에서는 `NoHitLast/First`, `NoFever`, `Sunset`, `SkyCoins`로 비트를 먼저 만들고, 나머지 챕터는 기존 통계형 미션에 **서사 문구**만 입힌다(예: CH8 "시장 골목에서 코인 80" → "시장 골목을 빠져나가며 동전 80").

### 4-5. 실패 시 플로우

```
러닝 중 체력 0  ──▶ 기존 「아쉽지만 다음에!」 ─ [다시하기] / [육성으로](페이즈 소비, 챕터 하트 보존)
도착(비트 실패) ─▶ 정산: ★1 ✓ ★2 ✗(회색, 이유 한 줄) ★3 ?  ─▶ 클로즈 컷씬 [비트==0] 분기 ─▶ 다음 챕터
도착(늦음)      ─▶ 기존 하트 ×0.6 + [늦음==1]  (비트와 독립, 둘 다면 ×0.6 한 번만)
CH20 비트 실패  ─▶ 정산 대신 "혼자 일어나야 해" 카드 ─ [다시] 만 (경성)
재도전          ─▶ 기존 IsRetry 경로. 비트 재판정 O, 미니게임 재실행 X(기존)
```
스토리 약화 분기는 컷씬 한두 줄 차이로 제한한다(대본 부담 최소). 게이트 실패(체력)와는 층이 다르므로 서로 영향 없음.

### 4-6. 엔딩·사이드 스토리 연결

- **별 총량**: 기존 팬아트(15별당 1장, 최대 4) 유지. 추가로 **비트 성공 수(★2 합계)** 를 `Save.beatCount`로 세어: ≥12 → END_A 계열 가중, ≤6 → END_B_WEAK 후보, CH18·CH20 비트 성공 + 비트 ≥14 → `trueEndingPending` 조건에 OR로 편입(현재 조건은 양쪽 엔딩 열람).
- **사이드 씬**(`SIDE_*` 49~60번, 옛 인물명)은 비트와 연결하지 않는다 — 인물 정리(§7) 뒤 결정.
- **레코드/포토카드**: 비트 성공 챕터의 포토카드 사인(S) 확률 +10%p(`Collection.OnChapterSettled` 훅).

### 4-7. 미니게임(`ChapterMission`) 재배치 — **유지**

| 안 | 판단 |
|---|---|
| 유지(5개, 롱컷 직전) | **권장.** 롱컷 앞의 호흡 전환 역할이 명확하고 코드가 완성돼 있음. 문구만 새 대본으로: 윷 "도담이보다" → "바다보다", 무궁화 술래 = 바다 |

## 7. Phasing — 기존 코드 재사용 우선

### P0 (1주) — 코드 재사용만으로 "한 곡 + 도장 + 서사 문구"
1. **`ArcadeRun.StartKpopDaily`**: `Start(Daily)`의 시드/조건/도장 + `StartKpop`의 스탯/챕터. 타이틀 K-POP 바가 이것을 호출. 「오늘의 런」 진입 제거(코드는 유지).
2. **90초 골인**: `KpopMode`일 때 `StageManager`의 아케이드 차단 3곳을 시간 조건으로 바꾼다 — (a) `_stageElapsed ≥ length−8s`에 `FinishRibbon.Spawn(현재거리 + 속도×8)` (b) 리본 통과 시 `ClearCurrent()` 허용 → `EnterStageClear`(여기서 `NoteKpopClear`가 비로소 동작) (c) 아웃트로 8초 장애물 스폰 정지. 피버 버튼은 `ArmForStage`를 K-POP에서도 호출하되 제안 타이밍만 후렴으로. 클리어 화면은 K-POP용 결과 카드(기존 `ShowRunOver` 변형).
3. **미션 3개**: `MakeConditions` 값 재조정 + `Finish` 고정 슬롯. HUD 칩 3개(`RunHudChrome`에 아이콘+숫자).
4. **BGM·후렴 피버**: `CoastBgmLibrary.Kpop()` → M2/M4/M7 랜덤(직전 곡 제외) + `AudioSource.time=start`. `KpopTrackMeta` 3줄(start/length/chorusStart/End) + 후렴 진입 시 `FeverMode` 제안 강제·코인 ×2 배너. 곡 창 끝 3초 페이드아웃(M4는 자연 종료).
5. **감쇠·상한**: `kpopRunsToday`로 코인 배율. 도장 +50G, 올클리어 +100G.
6. **스토리 P0**: `MissionKind`에 `NoHitFirst/NoHitLast/NoFever/Sunset/SkyCoins` 추가(`StageRunStats` 구간 피격 카운트·피버 카운트·하늘코인 카운트), `MissionTable`을 3슬롯(비트/별/별)로, 표의 P0 대체값 적용, 문구 서사화. `Save.chapterBeatMask` + `StoryCond` `[비트]` 태그 + 각 `_Close.txt`에 `[비트==0]` 한 줄. CH20 경성 처리.
7. 미니게임 문구 새 대본 인물로.

### P1 (2주차)
- 새 픽업 오브젝트 `Escort`(편지)·`Candle`(초) + 실패 연출 토스트. CH2·9·10·18 비트 교체.
- 별미션 2택(`MissionTable` 슬롯 4개, 챕터 진입 카드 UI).
- 주간 하이라이트 카드, 스트릭 보상 3/7일, 「어제 놓침 복구」.
- 하이라이트 레인, 후렴 진입 카메라 연출, 70% 조기 종료 도장.

### P2 (3주차 이후)
- `Pacer`(뒷모습 실루엣) 오브젝트 — CH3·11·16·19. `Stones` 순서 픽업 — CH4·14.
- 비트 성공 수 → 엔딩 가중치·`trueEndingPending` 편입.
- 스트릭 14/30일 보상(펫 색·칭호), K-POP 곡별 코스 스킨 지정(곡 ↔ 챕터 매핑표).
- 곡 추가 여부 검토(M1·M3·M5·M6 편입 시 `KpopTrackMeta` 한 줄씩).
